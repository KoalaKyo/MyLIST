# MyLIST V1 开发步骤规范

> 文档版本：V1.0  
> 状态：执行基线  
> 更新时间：2026-08-21  
> 产品真源：`MyLIST-Windows-开发需求文档.md` 与 `app/prototype` 当前原型

## 1. 开发原则

MyLIST V1 采用“小模块、可验证、逐项确认”的开发方式。每个模块只交付一个清晰目标，完成后先由开发者运行自动检查，再由产品方进行人工验收；未获得确认，不进入后续模块。

本规范优先保证数据安全、Windows 系统能力稳定、原型还原一致性，而非一次性追求全部功能完成。

### 1.1 模块门禁

每个模块必须满足以下条件：

1. 仅包含一个主业务目标；预计改动超过 8 个生产文件或 800 行有效代码时，必须拆分。
2. 有独立的本地 Git 分支与提交；提交信息包含模块编号、名称与验收结论。
3. 有自动测试结果、人工测试步骤、已知限制、回滚点。
4. 在 `docs/开发记录/` 写入模块验收记录。
5. 产品方人工确认通过后，才能开始下一个模块。

## 2. 固定技术与工程边界

| 层级 | 固定方案 | 责任 |
|---|---|---|
| 桌面运行时 | Tauri 2 | 窗口、托盘、权限、安装包、IPC |
| 界面 | React + TypeScript | 页面、组件、主题、交互、无障碍 |
| 业务与系统 | Rust | 领域规则、导入导出、Windows 能力 |
| 数据 | SQLite | 业务实体、设备设置、迁移、快照 |
| Windows 集成 | Rust + Win32 API/Tauri 插件 | 桌面层、置顶、托盘、单实例、启动项、顶部自动收起 |

- 首发仅支持 Windows 10 22H2、当前受支持的 Windows 11 与 x64 安装包。
- Android 暂不开发；后续仅复用 React 结构、领域模型、导入导出格式与设计令牌。
- 任务颜色只能继承分类颜色；无“未分类”系统类型、无任务级颜色覆盖。
- 设置修改立即生效；托盘菜单仅包含动态置顶切换、分隔线、退出。
- 开发依赖和缓存优先存放在项目目录或 `E:\下载`；系统工具维持 `D:\Program Files\` 下的安装路径。

## 4. 阶段实施细则

### 阶段 0：Windows 能力预研（强制前置）

目标是在进入业务开发前，确认 Windows 专有功能能够稳定实现。

- 验证 WorkerW/桌面宿主绑定、普通窗口之后显示、置顶切换与失败降级。
- 验证 Explorer 重启后自动重新绑定；失败时安全退化为非置顶窗口并重试。
- 验证关闭窗口隐藏到托盘、双击托盘恢复、托盘菜单置顶切换/退出、单实例唤醒。
- 验证 100%–200% DPI、显示器拔插、窗口可见区域修正。
- 本阶段不接入正式业务数据库，不制作完整 UI。

通过条件：Windows 10/11 各至少完成一次实测；任何不可靠行为必须先记录替代方案并重新评审。

### 阶段 1：工程基座与设计系统

- 初始化本地 Git；建立 React、TypeScript strict、Rust、SQLite、测试与构建目录。
- 建立设计令牌：浅色/深色表面、文字、确认色、危险色、间距、圆角、字号、阴影、300ms 动画。
- 建立主窗口、标题栏、分段页签、底栏、基础页面容器与顶层 Portal。
- 深色模式不得出现白色按钮或白色选中页签；浅色确认色为黑色、深色确认色为冷蓝。

通过条件：360×520 与 320×360 DIP、深浅色和键盘焦点均可查看；原型的标题栏、页签与底栏结构完成还原。

### 阶段 2：本地数据基础

- 创建顺序 SQLite migration；禁止手工修改已发布迁移。
- 建立 Task、Category、PaletteColor、DeviceSettings、ImportSnapshot 实体和仓储接口。
- 首次运行生成工作、个人、团队、生活、财务、学习、出行及中等明度默认色。
- 生成永久 UUID、deviceId，统一保存 UTC 时间、`revision`、`updatedByDeviceId`；不保存删除标记。
- 所有写入均使用事务；快照基础能力先落地，供后续导入使用。

通过条件：首次启动、重启、数据库迁移、事务失败均可预测；默认数据不重复创建。

### 阶段 3：任务核心

- 实现添加、查看、编辑、待办/已完成切换、完成、恢复、永久删除。
- 标题为 1–200 字符，备注为纯文本最多 2,000 字符；任务必须属于有效分类。
- 待办排序固定为：逾期、最近截止、有无截止时间、更新时间、UUID；已完成按完成时间倒序。
- 每次业务修改更新版本字段；删除立即物理清理本地记录，不提供回收站或跨设备删除传播。

通过条件：所有任务操作在重启后保持；同标题不同 UUID 的任务始终并存。

### 阶段 4：主界面精细交互

- 完整实现原型任务行、分类圆环、悬停操作、任务菜单、外部 Tooltip、右下拖拽热区。
- 完成/恢复/删除为两段确认，展开/收起均为 300ms，动画中禁止重复点击。
- 已完成删除确认胶囊始终右侧对齐，向左展开；标题可用宽度同步向左收缩 40 DIP，收起时同步恢复，完成时间保留。
- 标题不足宽度显示省略号；仅在真实截断时显示窗口外完整标题 Tooltip。

通过条件：完成/恢复与删除确认互斥但入口不消失；动画、菜单层级、时间隐藏与 Tooltip 均与原型一致。

### 阶段 5：设置与分类

- 常规页实现主题与随 Windows 启动；不提供通知权限或系统通知设置入口。
- 分类页实现 24 色浮层、添加“新分类”、编辑名称/颜色、保存、删除。
- 删除被引用分类时必须选择目标分类，迁移任务与永久删除分类在一个事务中完成。
- 数据页仅先完成入口与状态框架，实际导入导出留至阶段 8。

通过条件：设置立即生效；分类名去空格后不能为空、最长 20 字符且不重复；分类色在列表和浮层中完全一致。

### 阶段 6：截止时间与倒计时

- 日期时间输入按本地时区展示，内部 UTC 保存；打开但未选时间时默认为 18:00。
- 日期时间浮层通过 Portal 渲染，不能受页面滚动或窗口尺寸裁切。
- 实现动态倒计时、逾期和截止时间变更后的重算；不提供任务提醒设置或后台提醒调度。

通过条件：时区变更、截止边界和修改截止时间后的倒计时重算均通过测试。

### 阶段 7：Windows 生命周期、托盘与顶部自动收起

- 接入默认开启的当前用户启动项、关闭至托盘、显式退出和单实例恢复；启动项开关修改后即时生效，登录后显示主界面；不接入 Windows Toast、提醒权限、稍后提醒或补发服务。
- 托盘菜单提供“显示主界面”（桌面模式显示“显示桌面”）、分隔线、三种窗口模式和“退出”；窗口隐藏时切换普通/置顶模式先恢复窗口。
- 普通/置顶模式下，完成拖动且窗口顶部贴到任意显示器顶部时，窗口以 300ms 向上收起，仅留 1 DIP 标题栏色边缘；桌面模式不参与该行为。
- 禁止最大化：标题栏双击、拖至显示器顶端和系统最大化命令均不可最大化窗口，但窗口边缘与右下角热区的手动缩放保持可用。
- 收起后仅在对应显示器顶部、窗口水平范围内的 8 DIP 鼠标热区自动展开；鼠标离开窗口再次收起，拖离顶部则取消自动收起状态。切换到普通或置顶模式后，只要完整窗口仍贴顶即重新触发收起；隐藏到托盘、恢复、单实例唤醒和退出均先恢复完整窗口。
- 补充复制交互：查看事项可复制标题和非空备注，待办菜单可复制标题及换行后的备注；非输入区域不得被双击选择，输入框和文本域维持原生文本选择。

通过条件：关闭主窗口后进程与托盘仍在；主动退出才结束服务；三种模式、托盘恢复、多显示器/DPI 与顶部自动收起均正确。

### 阶段 8：导出、导入与合并

- 明文 `.dtodo.json` 与加密 `.dtodo` 都必须包含任务、分类与 24 色调色板；不包含删除记录。
- 加密固定使用 Argon2id + AES-256-GCM；密码为 6–32 个字符，不写盘、不写日志。
- 默认合并依次比较任务 UUID、`updatedAt`、`revision`、内容哈希、`updatedByDeviceId`；不同 UUID 不模糊合并。分类按名称匹配；同名分类颜色不同时，以导入文件颜色覆盖本地颜色。
- 导入顺序固定为：校验、预览、快照、调色板、分类、任务、引用修复、单事务提交、结果汇总。

通过条件：错误密码、损坏文件、版本过新、磁盘写入失败均不改变数据；双电脑往返合并只新增或更新，不会删除本地任务或分类。

### 阶段 8D：多语言基础与语言包

- 建立一个简体中文基准语言包与英语、德语、法语、意大利语、西班牙语、日语、繁体中文七个独立语言文件；本阶段非中文文件暂复制中文内容。
- React 界面、Toast、菜单、确认弹窗、无障碍标签、日期与相对时间格式、托盘菜单及文件对话框统一通过语言键获取文案；任务、备注和用户创建的分类名称不翻译。
- 在设备设置中持久化 `locale`，设置 → 常规提供语言下拉框，切换即时生效且不参与导入导出；首次默认 `zh-CN`。
- 语言包必须与中文基准保持同一键集；后续翻译以一个语言、少量键、人工视觉验收为一个独立小模块，不与功能开发混合。

通过条件：八种语言均可选择、重启后保持、托盘同步；350×530 DIP 与 150% DPI 下长文案不裁切或遮挡控件。

### 阶段 9：发布加固

- 创建每用户安装包与升级、卸载流程；卸载默认保留数据，删除数据单独确认。
- 验证代码签名、日志脱敏、数据库损坏保护、性能、无障碍、键盘操作和高 DPI。
- 在 Windows 10 22H2 与 Windows 11 真实环境完成完整回归。

通过条件：无已知静默丢失、重复、错误覆盖或安全泄露问题，才生成发布候选包。

## 5. 架构与代码规范

### 5.1 分层规则

```text
React UI → typed IPC DTO → Rust Application Service → Repository → SQLite / Windows Adapter
```

- React 仅保存视图状态、查询缓存和交互状态；不得直接访问文件、数据库、Win32 API、加密或 shell。
- Rust `domain` 放实体、校验、排序和版本规则；`application` 放用例；`infrastructure` 放 SQLite、文件、加密和日志；`platform/windows` 放 Windows adapter；`commands` 只做 IPC 参数转换。
- Windows adapter 通过接口注入，允许在非 Windows 或测试时替换模拟实现。
- IPC 使用显式 DTO、输入校验和稳定错误码；前端不得依赖 SQLite 表结构或 Rust 内部类型。

### 5.2 数据与安全规则

- 所有实体 UUID 永久稳定；禁止编辑、完成、恢复、导入导出过程中重建 ID。
- 所有时间按 UTC 保存、按系统本地时区展示；设备设置不参与导出合并。
- 多实体操作必须使用 SQLite 单事务；迁移只新增，不回写历史 migration。
- 禁止在用户输入、文件 I/O、数据库或系统调用中使用 Rust `unwrap`/`expect`；必须返回 `Result` 和可读领域错误。
- TypeScript strict；禁止 `any`、静默 `catch`、跨层导入、页面局部硬编码令牌值。
- 日志不得记录任务标题、备注、密码、完整导出内容或稳定设备标识；密码仅在内存短暂存在。

### 5.3 设计实现规则

- 颜色、字号、间距、圆角、阴影、动画时长只能引用设计令牌。
- 深浅色只替换令牌，不复制页面组件或业务逻辑。
- 所有菜单、日期时间、颜色、Tooltip 采用顶层 Portal，自动避让屏幕边缘。
- 每个按钮都必须定义正常、悬停、按下、键盘聚焦；禁用按钮另定义禁用态。
- 颜色不是唯一状态表达；逾期、完成、删除等状态必须有文字、图标或形状辅助。

## 6. 测试与人工验收规则

### 6.1 自动检查基线

每个模块至少执行与本模块相关的：

- TypeScript 类型检查、前端单元/组件测试。
- Rust 格式检查、Clippy、单元测试。
- SQLite 迁移和仓储集成测试。
- 涉及窗口、托盘、顶部自动收起、Explorer、DPI 时的 Windows adapter 测试。
- 涉及可见界面时的深浅色、最小尺寸、键盘焦点、浮层裁切视觉检查。

阶段 9 额外执行 release build、安装升级卸载、性能、安全与完整回归。

### 6.2 人工验收交付格式

每个模块结束时，开发者必须提供：

1. 本模块完成范围与未做内容。
2. 自动测试命令及通过结果。
3. 可点击的本地预览地址或可安装测试包。
4. 3–8 条按顺序执行的人工测试步骤。
5. 预期结果、已知限制和回滚方式。

产品方回复“通过”或明确同意后，才可启动下一模块；若发现问题，仅修复当前模块，不夹带下一模块功能。

## 7. 版本与协作管理

- 阶段 1 开始在 `E:\Codex\Todo_List` 初始化本地 Git；不自动创建远程仓库或上传代码。
- 分支命名：`m0x-简短英文模块名`；提交示例：`feat(m03): 完成任务核心并通过自测`。
- 每个模块通过后创建可读标签，例如 `v0.3-m03-approved`，作为回滚锚点。
- 需求变更先记录到对应开发记录和需求文档，再判断属于当前模块修复或后续模块新增。
- 不允许因“顺手修改”跨过模块边界；视觉微调也必须记录并验证深浅色影响。
