# 阶段 8B：明文导入预检与合并验收记录

状态：待人工验收

## 本次交付

- 数据页新增“导入事项和分类”单行入口，与导出入口采用相同布局和按钮规范。
- 仅允许选择 JSON 导出文件；文件在进入预览前完成 JSON、版本、UUID、24 色调色板、分类引用、事项状态与字段范围校验。
- 预检弹窗显示来源文件、任务/分类/调色板数量，以及任务和分类的新增、更新、保留数量。
- 确认导入时，先创建本机快照，再以单个 SQLite 事务完成导入；校验或写入失败不会修改业务数据。
- 任务仅按 UUID 合并：不存在则新增；同 UUID 按最后更新时间、修订号和设备 ID 判定较新版本；不同 UUID 即使标题相同也保留为独立事项。
- 分类按名称合并：本机没有则新增；同名但颜色不同则以导入文件颜色覆盖本机颜色。导入不会删除本地事项或分类。
- 预检确认后刷新任务与分类数据，并以标题栏提示展示新增和更新数量。
- 明文导出默认文件名调整为 `MyLIST_data_yyyy-mm-dd.dtodo.json`；若同目录存在同名文件，自动使用 ` (1)`、` (2)` 等后缀，避免覆盖。

## 自动验证

- `npm run build`：通过。
- `cargo test`：通过。
- Debug EXE：构建并启动成功。

## 人工验收

1. 在“设置 → 数据”点击“导出”，连续两次保存到同一目录，确认旧文件不被覆盖，第二个文件带 `(1)` 后缀。
2. 点击“导入”，选择刚导出的文件，确认出现“导入预检”并显示正确的任务、分类、调色板数量；点击“取消”后本机数据不变。
3. 点击“确认导入”，确认任务列表和分类页自动刷新；再次导入同一文件时应全部保留、不生成重复事项。
4. 用另一份导出文件验证：新 UUID 任务被新增；同 UUID 且较新的任务更新；同名不同色分类颜色被覆盖。
5. 选择非 JSON、手动损坏 JSON 或密码文件，确认显示简短错误提示且本机数据不变。
